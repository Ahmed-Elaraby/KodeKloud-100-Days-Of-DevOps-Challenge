# Day 018: Install and Configure MariaDB Server

## 🎯 What I Did Today

Today's task was very similar to Day 17, but with MariaDB instead of PostgreSQL — 
install the database server from scratch (notpre-installed this time), 
then create a database and a user with full permissions.

**The scenario**: install/configure MariaDB on the Nautilus DB Server, create a database
`kodekloud_db5`, create a user `kodekloud_tim` with password `BruCStnMT5`, and grant that
user full permissions on the database.


## Steps I Followed

1. Connected to the DB server.

2. Installed MariaDB:

    ```sh
    sudo yum install mariadb-server -y
    ```

3. Started it and made sure it comes back up on reboot:

    ```sh
    sudo systemctl start mariadb
    sudo systemctl enable mariadb
    ```

4. Confirmed it was actually running before doing anything else:

    ```sh
    sudo systemctl status mariadb
    ```

5. Logged into MariaDB as root:

    ```sh
    sudo mysql
    ```

6. Created the database:

    ```sql
    CREATE DATABASE kodekloud_db5;
    ```

7. Created the user with the required password, scoped to `localhost`:

    ```sql
    CREATE USER 'kodekloud_tim'@'localhost' IDENTIFIED BY 'BruCStnMT5';
    ```

   Kept in mind that if the user needed to connect from somewhere other than the DB server
   itself, a second user entry with `'%'` as the host would be needed — MariaDB treats
   `user@localhost` and `user@%` as genuinely different accounts, not the same user with
   broader access.

8. Granted full privileges on the database to the user:

    ```sql
    GRANT ALL PRIVILEGES ON kodekloud_db5.* TO 'kodekloud_tim'@'localhost';
    ```

9. Applied the privilege changes:

    ```sql
    FLUSH PRIVILEGES;
    ```

10. Verified everything before trusting it:

    ```sql
    SHOW DATABASES;
    SELECT User, Host FROM mysql.user WHERE User='kodekloud_tim';
    SHOW GRANTS FOR 'kodekloud_tim'@'localhost';
    ```

11. Exited, then did a real connection test instead of just trusting the SQL:

    ```sh
    mysql -u kodekloud_tim -p kodekloud_db5
    ```

    Prompted for the password, and connecting cleanly confirmed the setup actually worked
    end-to-end.

## What I Took Away From This

- `'user'@'localhost'` and `'user'@'%'` are two separate accounts in MySQL/MariaDB, not one
  account with different access levels — this matters a lot if something later needs remote
  access and only the `localhost` version was created
- This task and Day 17 were the same underlying skill (create user, create database, grant
  privileges, verify) just on two different database engines — the concepts transfer, only
  the exact syntax changes
- `FLUSH PRIVILEGES` after a `GRANT` is easy to forget, and skipping it can make it look
  like the grant didn't work when it actually just hasn't been applied yet
- The real verification is always the same pattern I used on Day 17 too: don't just check
  that the SQL ran without error, actually connect as the new user and confirm access works

## Notes to Self

| Command | Purpose |
|---|---|
| `CREATE DATABASE db;` | Create a new database |
| `CREATE USER 'user'@'host' IDENTIFIED BY 'pass';` | Create a new user scoped to a specific host |
| `GRANT ALL PRIVILEGES ON db.* TO 'user'@'host';` | Grant full privileges on a specific database |
| `FLUSH PRIVILEGES;` | Apply privilege changes immediately |
| `SHOW GRANTS FOR 'user'@'host';` | Confirm exactly what privileges a user has |

| Host Value | Meaning |
|---|---|
| `'localhost'` | User can only connect from the DB server itself |
| `'%'` | User can connect from anywhere (remote access) |
| `'192.168.1.%'` | User can connect from a specific subnet only |
