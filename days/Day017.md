# Day 017: Install and Configure PostgreSQL

## 🎯 What I Did Today

Day 17 of my #100DaysOfDevOps challenge. Today's task was database prep work — PostgreSQL
was already installed, and the job was just creating a user and a database for an
upcoming app deployment, with a hard rule not to touch the running service.

**The scenario**: create a database user `kodekloud_cap` with password `YchZHRcLkL`, create
a database `kodekloud_db1`, and grant that user full permissions on it. Explicitly told not
to restart the PostgreSQL service.

## Steps I Followed

1. Connected to the database server.

2. Switched into the `postgres` admin user:

    ```sh
    sudo su - postgres
    psql
    ```

3. Created the user with the required password:

    ```sql
    CREATE USER kodekloud_cap WITH PASSWORD 'YchZHRcLkL';
    ```

4. Created the database:

    ```sql
    CREATE DATABASE kodekloud_db1;
    ```

5. Granted full privileges to the user on that database:

    ```sql
    GRANT ALL PRIVILEGES ON DATABASE kodekloud_db1 TO kodekloud_cap;
    ```

6. Went a step further and made the user the actual owner of the database — `GRANT ALL
   PRIVILEGES ON DATABASE` alone only covers database-level rights (like CONNECT and
   CREATE), not everything you'd expect from "full permissions" in newer PostgreSQL
   versions, so ownership is the safer, more complete guarantee:

    ```sql
    ALTER DATABASE kodekloud_db1 OWNER TO kodekloud_cap;
    ```

7. Verified everything:

    ```sql
    \l
    ```

   Confirmed `kodekloud_db1` existed with `kodekloud_cap` as owner.

    ```sql
    \du
    ```

   Confirmed `kodekloud_cap` existed as a role.

8. Exited:

    ```sql
    \q
    ```

9. Did a real end-to-end test instead of just trusting the SQL ran — actually connected as
   the new user to the new database:

    ```sh
    psql -U kodekloud_cap -d kodekloud_db1 -h localhost -W
    ```

   Prompted for the password, and connecting cleanly confirmed the whole setup actually
   worked, not just that the commands didn't error.

## What I Took Away From This

- `GRANT ALL PRIVILEGES ON DATABASE` isn't automatically the same as "full ownership" in
  newer PostgreSQL — if the intent is genuinely full control, setting ownership explicitly
  with `ALTER DATABASE ... OWNER TO ...` is the safer move
- "Don't restart the service" made sense once I thought about it — creating a user or
  database is a live SQL operation, it was never going to require a restart in the first
  place. The note was really just making sure I didn't reach for a restart out of habit
- Verifying with `\l` and `\du` is good, but actually connecting as the new user is the real
  proof — SQL commands succeeding doesn't guarantee the end-to-end access actually works
- There's also a one-line bash version of all of this using `sudo -u postgres psql -c
  "..."` for each statement, useful when you don't need to sit inside an interactive shell

## Notes to Self

| Command | Purpose |
|---|---|
| `CREATE USER name WITH PASSWORD 'pass';` | Create a new role that can log in |
| `CREATE DATABASE name;` | Create a new database |
| `GRANT ALL PRIVILEGES ON DATABASE db TO user;` | Grant database-level privileges |
| `ALTER DATABASE db OWNER TO user;` | Make the user the actual owner — broader than GRANT alone |
| `\l` | List all databases and their owners |
| `\du` | List all roles/users |
| `\q` | Exit the psql shell |

| Testing Connection | Command |
|---|---|
| Connect as a specific user to a specific DB | `psql -U user -d dbname -h localhost -W` |
