# Day 006: Setup a Cron Job


## 🎯 What I Did Today

Day 6 of my #100DaysOfDevOps challenge. Today's task was about scheduling — installing the
cron service and setting up a recurring job for the root user, as a small test before
similar scripts get rolled out across all app servers.

**The scenario**: install `cronie` and get `crond` running on the app servers, then add a
cron job for root that runs every 5 minutes.


## Steps I Followed

1. SSH'd into the server the same way as previous days.

2. Installed the `cronie` package (this is CentOS, so it's not installed by default):

    ```sh
    sudo yum install cronie -y
    ```

3. Enabled and started the `crond` service so it's running now and comes back up on boot:

    ```sh
    sudo systemctl enable crond
    sudo systemctl start crond
    ```

4. Added the cron job for root:

    ```sh
    sudo crontab -e
    ```

    With this line:

    ```
    */5 * * * * echo hello > /tmp/cron_text
    ```

5. Verified it was actually scheduled, then waited to confirm it was actually running:

    ```sh
    sudo crontab -l
    ```

    Checked `/tmp/cron_text` a few minutes later to confirm the job was firing on schedule.

## Turning It Into a Reusable Script

Since this is meant to be rolled out to multiple servers, I wrapped the steps into a small
idempotent script — one that checks before it acts, so re-running it doesn't break anything
or duplicate the cron entry:

```sh
#!/bin/sh
set -e

echo "=== Setting up Cron Job on CentOS ==="

# Install cronie only if it's not already there
if ! rpm -q cronie &>/dev/null; then
    sudo yum install cronie -y
    echo "✓ cronie installed"
else
    echo "✓ cronie already installed"
fi

# Start + enable crond
sudo systemctl start crond
sudo systemctl enable crond

if systemctl is-active --quiet crond; then
    echo "✓ crond is running"
else
    echo "✗ crond failed to start"
    exit 1
fi

# Add the cron job only if it isn't already there
CRON_JOB="*/5 * * * * echo hello > /tmp/cron_text"

if sudo crontab -l 2>/dev/null | grep -q "echo hello > /tmp/cron_text"; then
    echo "✓ Cron job already exists"
else
    (sudo crontab -l 2>/dev/null || true; echo "$CRON_JOB") | sudo crontab -
    echo "✓ Cron job added"
fi

echo "Current cron jobs for root:"
sudo crontab -l
```

## What I Took Away From This

- Checking before acting (`rpm -q`, `grep -q` on the existing crontab) is what makes a
  script safe to re-run — without that, running it twice would duplicate the cron entry
- `systemctl enable` and `systemctl start` are two different things — enable makes it
  survive a reboot, start makes it run now. Forgetting one or the other is an easy mistake
- Cron runs with a very minimal environment, so anything beyond a trivial command usually
  needs absolute paths and explicit environment variables to behave the same way it does
  when run manually

## Notes to Self

| Field | Range |
|---|---|
| Minute | 0–59 |
| Hour | 0–23 |
| Day of month | 1–31 |
| Month | 1–12 |
| Day of week | 0–7 |

| Special Character | Meaning |
|---|---|
| `*` | Any value |
| `,` | List of values |
| `-` | Range of values |
| `/` | Step value |

| Crontab Type | Location / Command |
|---|---|
| User crontab | `crontab -e` (per-user) |
| System crontab | `/etc/crontab` |
| Drop-in cron dirs | `/etc/cron.d/`, `/etc/cron.daily/` |
