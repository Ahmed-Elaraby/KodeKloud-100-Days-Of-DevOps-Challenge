# Day 015: Setup SSL for NGINX

## 🎯 What I Did Today

Today's task was preparing a server for an upcoming app deployment — 
installing Nginx, wiring up a self-signed SSL certificate, and
making sure the server actually responds over HTTPS.

**The scenario**: install and configure Nginx on App Server 2, deploy an existing
self-signed cert/key (sitting in `/tmp`) into an appropriate location, create an
`index.html` with the content `Welcome!`, and confirm from the jump host that
`curl -Ik https://<app-server-name>/` works.


## Steps I Followed

1. Connected to App Server 2.

2. Installed Nginx:

    ```sh
    sudo yum install nginx -y
    ```

3. Moved the certificate and key out of `/tmp` into a dedicated SSL directory instead of
   leaving them in a temp location:

    ```sh
    sudo mkdir -p /etc/nginx/ssl
    sudo mv /tmp/nautilus.crt /etc/nginx/ssl/
    sudo mv /tmp/nautilus.key /etc/nginx/ssl/
    ```

   Locked down the permissions, especially on the private key:

    ```sh
    sudo chmod 600 /etc/nginx/ssl/nautilus.key
    sudo chmod 644 /etc/nginx/ssl/nautilus.crt
    ```

4. Confirmed Nginx's document root:

    ```sh
    sudo grep -r "root" /etc/nginx/nginx.conf
    ```

5. Created the `index.html` with the required content:

    ```sh
    sudo sh -c 'echo "Welcome!" > /usr/share/nginx/html/index.html'
    ```

6. Configured a server block listening on `443` with SSL, pointing at the cert/key and the
   document root:

    ```sh
    sudo nano /etc/nginx/nginx.conf
    ```

    ```nginx
    server {
        listen 443 ssl;
        server_name stapp02;

        ssl_certificate /etc/nginx/ssl/nautilus.crt;
        ssl_certificate_key /etc/nginx/ssl/nautilus.key;

        root /usr/share/nginx/html;
        index index.html;

        location / {
            try_files $uri $uri/ =404;
        }
    }
    ```

7. Tested the config for syntax errors *before* touching the running service — this is the
   step that saves you from breaking Nginx with a typo:

    ```sh
    sudo nginx -t
    ```

8. Once that came back clean, restarted and enabled the service:

    ```sh
    sudo systemctl restart nginx
    sudo systemctl enable nginx
    sudo systemctl status nginx
    ```

9. Opened the HTTPS port on the firewall, just in case:

    ```sh
    sudo firewall-cmd --permanent --add-service=https
    sudo firewall-cmd --reload
    ```

10. Tested from the jump host:

    ```sh
    curl -Ik https://stapp02/
    ```

    `-I` grabs just the headers, and `-k` skips certificate validation — necessary here
    since a self-signed cert isn't trusted by default and `curl` would otherwise reject it.
    Confirmed a `200 OK`, then checked the actual content too:

    ```sh
    curl -k https://stapp02/
    ```

    Got back `Welcome!` as expected.

## What I Took Away From This

- `nginx -t` before every restart is non-negotiable once SSL config is involved — one typo
  in the `server` block can take the whole service down, and testing first catches that
  before it becomes an outage
- `-k` in curl isn't a "just in case" flag here, it's required — self-signed certs will
  always fail default validation, and that's expected, not a sign something's broken
- Where you put the cert/key matters for both organization and security — `/etc/nginx/ssl/`
  with locked-down permissions (`600` on the key) is a much better home than leaving
  anything in `/tmp`
- Setting up a clean, explicit `server { listen 443 ssl; ... }` block rather than blindly
  editing whatever default block exists keeps the config easier to reason about later

## Notes to Self

| SSL/TLS Concept | Detail |
|---|---|
| Certificate | Contains the public key + identity info |
| Private key | Must stay secure — this is what decrypts traffic |
| Self-signed cert | Works for encryption, but isn't trusted by browsers/curl by default |

| Nginx SSL Directive | Purpose |
|---|---|
| `ssl_certificate` | Path to the `.crt`/`.pem` file |
| `ssl_certificate_key` | Path to the private `.key` file |
| `listen 443 ssl` | Enables SSL on that server block |

| File/Path | Recommended Permissions |
|---|---|
| Private key | `600` |
| Certificate | `644` |
