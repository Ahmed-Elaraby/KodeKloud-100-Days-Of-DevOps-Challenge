# Day 010: Create a Bash Backup Script


## 🎯 What I Did Today

Today's task pulled together a few things fromearlier days — 
SSH key auth, permissions, and now actual scripting — 
into one real backup script.

**The scenario**: write a script `beta_backup.sh` (placed under `/scripts` on App Server 3)
that zips a website directory, saves it locally as a temporary backup, and also copies it
to the Nautilus Backup Server — all without prompting for a password, and runnable by the
server's own sudo user.


## Steps I Followed

1. Generated an SSH key on App Server 3 and copied the public key to the backup server —
   exact same pattern as [Day 7](./day-007-linux-ssh-automation.md), just applied to a
   different server pair. This is what makes the "no password prompt" requirement possible.

2. Wrote the script at `/scripts/beta_backup.sh`:

    ```sh
    #!/bin/sh

    zip -r /backup/xfusioncorp_beta.zip /var/www/html/beta
    scp /backup/xfusioncorp_beta.zip clint@stbkp01:/backup/
    ```

    - `zip -r` archives the website directory into `/backup/` locally (the "temporary"
      copy that gets cleaned weekly)
    - `scp` then pushes that same archive to the backup server, using the key-based auth
      set up in step 1 so no password prompt interrupts the script

3. Made the script executable so the server's user can actually run it:

    ```sh
    chmod +x /scripts/beta_backup.sh
    ```

## What I Took Away From This

- This task was really a combination of three earlier skills: SSH key auth (Day 7), file
  permissions (Day 4), and now writing the actual automation logic — none of the earlier
  days were standalone, they build on each other
- A backup script that still asks for a password isn't actually automation — it just moves
  the manual step from "run the backup" to "type the password when the backup runs"
- Local + remote copy is a common backup pattern: keep a short-lived local copy for quick
  recovery, but always ship a copy somewhere else too, since local-only backups don't
  survive the server itself failing

## Notes to Self

| Bash Scripting Practice | Why It Matters |
|---|---|
| Shebang (`#!/bin/sh` or `#!/bin/bash`) | Tells the system which interpreter to use |
| `set -e` | Exits the script on the first error instead of continuing silently |
| Quote variables (`"$variable"`) | Prevents word-splitting / unexpected behavior on paths with spaces |
| Functions | Break complex scripts into smaller, reusable pieces |

| Archive Tool | Notes |
|---|---|
| `zip -r archive.zip dir/` | Cross-platform, what I used today |
| `tar -czf archive.tar.gz dir/` | The more common Unix-native option |

| Remote Copy Method | Use Case |
|---|---|
| `scp` | Simple secure copy over SSH — what I used today |
| `rsync` | Better for repeated/incremental syncs, only transfers changes |
| `sftp` | Interactive file transfer session |
