# Day 011: Install and Setup Tomcat Server

## 🎯 What I Did Today

Today's task was deploying a Java web applicationusing Tomcat —
Installing the server, changing its default port, and deploying a `.war`
file so it serves directly from the base URL instead of a sub-path.

**The scenario**: install Tomcat on App Server 1, configure it to run on port `6100`, then
deploy a `ROOT.war` file (sitting on the jump host at `/tmp`) so the app is reachable
directly at `curl http://stapp01:6100`.


## Steps I Followed

1. Connected to App Server 1.

2. Made sure Java was available first, since Tomcat won't run without it:

    ```sh
    java -version
    ```

    Installed it if missing:

    ```sh
    sudo yum install java-1.8.0-openjdk -y
    ```

3. Installed Tomcat. There are two ways this can go — the package-manager way if the repo
   has it, or the manual download-and-extract way (which is what I ended up using):

    ```sh
    cd /tmp
    wget https://downloads.apache.org/tomcat/tomcat-9/v9.0.XX/bin/apache-tomcat-9.0.XX.tar.gz
    sudo tar -xzf apache-tomcat-9.0.XX.tar.gz -C /usr/local/
    sudo mv /usr/local/apache-tomcat-9.0.XX /usr/local/tomcat
    ```

4. Changed the default port from `8080` to `6100`. Found the config file first (paths can
   vary depending on how Tomcat was installed):

    ```sh
    sudo find / -name "server.xml" 2>/dev/null
    sudo nano /usr/local/tomcat/conf/server.xml
    ```

    Changed:

    ```xml
    <Connector port="8080" protocol="HTTP/1.1"
    ```

    to:

    ```xml
    <Connector port="6100" protocol="HTTP/1.1"
    ```

5. Started Tomcat and made sure it comes back up on reboot:

    ```sh
    sudo systemctl start tomcat
    sudo systemctl enable tomcat
    sudo systemctl status tomcat
    ```

6. Copied `ROOT.war` from the jump host to App Server 1:

    ```sh
    scp /tmp/ROOT.war tony@stapp01:/tmp/
    ```

7. Deployed it into Tomcat's `webapps` directory — keeping the exact name `ROOT.war` is
   what makes it deploy to the base URL instead of a `/appname` sub-path. Also had to clear
   out any existing default `ROOT` folder first so it wouldn't conflict:

    ```sh
    sudo find / -name "webapps" -type d 2>/dev/null
    sudo rm -rf /usr/local/tomcat/webapps/ROOT
    sudo cp /tmp/ROOT.war /usr/local/tomcat/webapps/
    ```

8. Restarted Tomcat so it extracts the war file, then confirmed the extraction happened:

    ```sh
    sudo systemctl restart tomcat
    sudo ls -la /usr/local/tomcat/webapps/
    ```

    A new `ROOT` directory showing up here (auto-generated from the war file) is the sign
    it worked.

9. Tested it:

    ```sh
    curl http://stapp01:6100
    ```

## What I Took Away From This

- The file name matters as much as the location — `ROOT.war` specifically deploys to the
  base URL, any other name deploys under a `/appname` path instead
- Config file paths aren't fixed — they depend on how the software was installed (package
  manager vs. manual extract), so `find` was more reliable than assuming a path
- Tomcat needs a moment after restart to actually extract the `.war` file — checking
  `webapps/` for the auto-generated folder is a better verification step than testing the
  URL immediately
- Clearing out a conflicting default folder before deploying is a step that's easy to
  forget and causes confusing results if skipped

## Notes to Self

| Tomcat Concept | Detail |
|---|---|
| Catalina | The servlet container itself |
| Coyote | The HTTP connector |
| Jasper | The JSP engine |
| Default ports | 8080 (HTTP), 8443 (HTTPS), 8005 (shutdown) |

| Directory | Purpose |
|---|---|
| `bin/` | Startup/shutdown scripts |
| `conf/` | Configuration (`server.xml`, `web.xml`, etc.) |
| `webapps/` | Deployed applications |

| Common Issue | Fix |
|---|---|
| Port already in use | Check nothing else is bound to that port |
| Firewall blocking access | `firewall-cmd --add-port=<port>/tcp --permanent && firewall-cmd --reload` |
| Getting a 404 | War file name/deployment path is likely wrong, or extraction hasn't finished |
