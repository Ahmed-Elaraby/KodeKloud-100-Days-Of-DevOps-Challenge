# Day 002: Temporary User Setup with Expiry Date


## 🎯 What I Did Today

Today's scenario: a developer is joining a projectfor a limited time,
so instead of creating a regular account I need to create one 
thatautomatically expires — no need to remember to come back and disable it manually later.

**The scenario**: create a user named `yousuf` with the account set to expire on
`2024-01-28`.


## Steps I Followed

1. SSH'd into the server the same way as Day 1.

2. Created the user with an expiry date set directly at creation time:

    ```sh
    sudo useradd -m -e 2024-01-28 yousuf
    ```

    - `-e` sets the account expiry date, format `YYYY-MM-DD`
    - `-m` still creates the home directory, same as before

3. Verified it:

    ```sh
    cat /etc/passwd
    sudo su yousuf
    sudo chage -l yousuf
    ```


## What I Took Away From This

- Setting an expiry date at creation time (`-e`) is a much cleaner approach than relying on
  someone to manually disable an account later
- `chage -l username` is the command to actually check an account's expiry/aging info
- If a temporary assignment gets extended, `sudo chage -E new-date username` updates the
  expiry without recreating the user
- Expired accounts don't disappear — they just can't log in anymore. Full removal still
  needs `userdel -r username`

## Notes to Self

| Concept | Command / Detail |
|---|---|
| Set expiry at creation | `useradd -e YYYY-MM-DD username` |
| Check account expiry/aging | `chage -l username` |
| Extend/change expiry on existing user | `sudo chage -E YYYY-MM-DD username` |
| Modify expiry via usermod | `usermod -e YYYY-MM-DD username` |
| Check password status | `passwd -S username` |
| Fully remove an expired user | `userdel -r username` |
