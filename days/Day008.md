# Day 008: Setup Ansible

## 🎯 What I Did Today

Today's task was the first step into configurationmanagement — 
Installing Ansible on the jump host so it can act as the control node 
for managing the rest of the servers.

**The scenario**: install Ansible version `4.8.0` on the jump host using `pip3` only, and
make sure the binary is available globally — every user on that system should be able to
run Ansible commands, not just the one who installed it.

## Steps I Followed

1. SSH'd into the jump host.

2. Installed the specific Ansible version with `pip3`, using `sudo` so it installs at the
   system level and ends up available to every user rather than just my own user:

    ```sh
    sudo pip3 install ansible==4.8.0
    ```

   The `sudo` here is the detail that actually matters — a plain `pip3 install` without it
   would put Ansible somewhere only I could use, which fails the "globally available"
   requirement.

## What I Took Away From This

- Ansible is agentless — nothing gets installed on the servers it manages, it just needs
  SSH access to them. That's a big part of why the team picked it for a simple first step
- Pinning an exact version (`==4.8.0`) matters in real environments — playbooks and
  collections can behave differently across versions, so "whatever pip installs by default"
  isn't good enough for anything beyond a quick test
- Where you install something (system-wide vs. user-level) is just as important as how —
  `sudo pip3 install` vs `pip3 install --user` give very different results for who can
  actually run the tool afterward

## Notes to Self

| Ansible Concept | What It Is |
|---|---|
| Control node | The machine running Ansible (the jump host, in this case) |
| Managed nodes | The target servers being configured |
| Inventory | The list of managed nodes and how they're grouped |
| Playbook | YAML file defining the automation tasks |
| Module | A reusable unit of work (e.g. `copy`, `service`, `user`) |

| Install Method | Notes |
|---|---|
| `pip3 install ansible` | Python package manager — what I used today |
| `yum install ansible` | OS package manager |
| Git source | For development/unreleased versions |
| Virtual environment | Keeps the install isolated from system Python |
