# Day 003: Secure SSH Root Access

## 🎯 What I Did Today
Today's task was about locking down SSH — disablingdirect root login on the app servers 
so nobody can SSH in as root directly.

**The scenario**: disable SSH root access on all app servers.

## Steps I Followed

1. SSH'd into the server the same way as previous days.

2. Edited `sshd_config` to turn root login off, then restarted the SSH service so the
   change actually takes effect:

    ```sh
    sudo sed -i 's/PermitRootLogin yes/PermitRootLogin no/g' /etc/ssh/sshd_config
    sudo systemctl restart sshd
    ```

    - `sed -i` edits the file in place, swapping `PermitRootLogin yes` → `PermitRootLogin no`
    - Restarting `sshd` is required — editing the config file alone doesn't apply anything
      until the service reloads it

## What I Took Away From This

- Disabling root login is one of the most basic but most important SSH hardening steps —
  every admin action should go through a named user + `sudo`, not a shared root login
- A config change to `sshd_config` does nothing on its own — the service has to be
  restarted (or reloaded) to pick it up
- This pairs naturally with the earlier user-management tasks: named accounts + no direct
  root login = actual accountability for who did what

## Notes to Self

| Concept | Detail |
|---|---|
| Disable root login | `PermitRootLogin no` in `/etc/ssh/sshd_config` |
| Disable password auth (keys only) | `PasswordAuthentication no` |
| Enable key-based auth | `PubkeyAuthentication yes` |
| Change default SSH port | `Port 2222` (or any non-default port) |
| Apply config changes | `sudo systemctl restart sshd` |
